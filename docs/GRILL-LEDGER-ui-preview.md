ทำรุ่นทดลองที่อ่านง่ายและทำข้อเสนอแลกคาบพร้อมตารางจำลองก่อนอนุมัติได้ เปิดด้วยอีกลิงก์เพื่อเปรียบเทียบกับเว็บเดิม โดยรักษาเว็บเดิมไว้ใช้งานต่อและใช้ข้อมูลจริงชุดเดียวกันเป็นฐาน

## การตัดสินใจที่ยืนยันแล้ว

- D01: เก็บหน้าเว็บเดิมที่ `/schedule-swap-pp/` ไว้ ไม่ลบ ไม่เปลี่ยนเส้นทาง และไม่แทนที่ด้วยรุ่นใหม่
- D02: รุ่นใหม่เป็นอีกลิงก์ใต้เว็บไซต์เดิม เสนอเส้นทาง `/schedule-swap-pp/preview/` (ยังไม่ได้สร้าง/เผยแพร่)
- D03: ใช้ข้อมูลจริงชุดเดียวกับที่ผู้ใช้ใช้ในเว็บเดิม ไม่ใช้ข้อมูลสมมติเป็นเนื้อหาการทดลองของผู้ใช้
- D04: ความหมายของ D03 คือข้อมูลต้นทางชุดเดียวกัน ไม่ใช่เชื่อมการบันทึกสองเว็บเข้าหากัน ผู้ใช้แก้ความเข้าใจเมื่อ 11 พ.ย. ว่านึกว่าคำถามเดิมหมายถึงข้อมูลสมมติ ข้อเลือก “ใช้ข้อมูลร่วม” ก่อนหน้านั้นจึงไม่ใช่อำนาจให้เขียนทับคลังเว็บเดิม
- D05: SUPERSEDED — ผู้ใช้ตอบ “โอเค เริ่มได้ครับ” อนุมัติเริ่ม S01 ตามข้อเสนอสร้างและเผยแพร่รุ่นทดลอง; S02–S07 รอ gate ทีละขั้น

## แนวทางที่เสนอเพื่ออนุมัติ

### แยกเว็บและการบันทึก แต่เริ่มจากข้อมูลจริงชุดเดียวกัน

- ใช้ `preview/index.html` เป็นรุ่นทดลอง โดยเริ่มต่อจากโปรแกรมเดิมที่ใช้งานได้ ไม่รื้อเครื่องคำนวณหรือเพิ่มระบบหลังบ้านใหม่
- ลิงก์เว็บเดิมใช้ไฟล์เดิม รุ่นทดลองไม่แก้ `index.html` ที่ราก ไม่ทำ redirect ไม่ลบหน้าเก่า
- รุ่นทดลองมีป้าย “รุ่นทดลอง” และปุ่มกลับเว็บเดิม ส่วนเว็บเดิมไม่ต้องเพิ่มปุ่มเพราะผู้ใช้ต้องการเก็บหน้าเดิมไว้
- ใช้ที่เก็บข้อมูลคนละชื่อ เช่น `swapApp.preview.v1` เทียบกับเดิม `swapApp.v1` รวมถึงค่าการแสดงผลและข้อมูลช่วยจำที่รุ่นทดลองเขียน
- ครั้งแรกมีคำสั่ง “คัดลอกข้อมูลจากเว็บเดิม” ที่อ่านคลังเดิมอย่างเดียว แสดงภาคเรียนและจำนวนข้อมูลก่อนยืนยันสร้างสำเนา ไม่เขียนกลับคลังเดิม ไม่คัดลอกซ้ำทุกครั้งที่เปิด
- ถ้าคนละเบราว์เซอร์/เครื่องหรือเข้าไม่ถึงคลังเดิม ให้นำเข้าไฟล์สำรองจริงจากเว็บเดิม โดยคงวิธีสำรอง/กู้คืนเดิม
- หลังคัดลอก การเปลี่ยนแปลงของแต่ละเว็บแยกกัน แสดงวันเวลาที่คัดลอกไว้ หากจะเริ่มเทียบใหม่ให้สำรองรุ่นทดลองก่อนแทนที่ข้อมูลสำเนา ไม่ผสานอัตโนมัติ
- ไฟล์เว็บที่เผยแพร่ต้องไม่มีข้อมูลจริงฝังอยู่ ข้อมูลจริงอยู่เฉพาะเครื่องเหมือนเดิม
- ข้อมูลที่กำลังจำลองไม่ใช่รายการอนุมัติ และไม่สร้างการจองคาบจริงจากการเปิดดู
- ไม่ย้ายข้อมูลกลับไปใช้จริงอัตโนมัติ การจะเลื่อนรุ่นใหม่เป็นเว็บหลักหรือย้ายผลทดลองกลับเป็นงานคนละช่วงภายหลัง

### รูปแบบหน้าจอที่เสนอ

งานหลัก 3 พื้นที่: “จัดคาบที่ลา / ข้อเสนอและงานค้าง / ตารางและเอกสาร” ตั้งค่าและคู่มือเป็นงานรอง

ผลค้นหาชั้นแรก: ชื่อคู่สลับ วันและคาบจริง ภาระก่อน/หลัง ข้อควรตกลง และปุ่มดูจำลอง/บันทึก รายละเอียดคะแนน การเดิน และข้อมูลดิบพับได้

ตารางมี 3 มุมมอง: ตารางเดิม, จำลองข้อเสนอที่เลือก, ตารางตามอนุมัติ พร้อมดูทั้งสองฝ่าย ไม่แสดงข้อเสนอทุกตัวเลือกซ้อนกัน

| S02 — ตัวอย่างหน้าจอ | จัดหน้าแรกและผลค้นหาใหม่ให้เห็นทิศทาง ตัดตารางสีตกแต่ง ใช้ภาษาไทยแทน Me/Y | ผู้ใช้ลองเลือกครู/วันลา/คาบ เปิดคู่สลับ และเข้าถึงข้อมูลหลักได้; รอบนี้ยังไม่เปลี่ยนสูตรคะแนน |
| S03 — แก้ความถูกต้อง | ภาระตามวันที่จริง คาบคืนกับช่วงลา และความหมายวิชา/ห้องตรงทุกหน้า รวมการเลือกครูไม่ค้างคนเดิม | เคสบั๊กต้องแสดงข้อผิดพลาดก่อนแก้แล้วผ่านหลังแก้; ค่าคาดหวังคำนวณอิสระ; ทดสอบเดิมที่ไม่เกี่ยวข้องยังผ่าน |
| S04 — ตารางจำลอง | ปุ่มจำลองจากคู่ที่เลือก ดูก่อน/หลังทั้งสองคน พิมพ์/บันทึก PDF พร้อมคำว่า “ข้อเสนอ — ยังไม่อนุมัติ” | เปิด/พิมพ์ได้โดยไม่ต้องอนุมัติหรือบันทึกลงทะเบียน; ไม่เปลี่ยนสถานะ/การจองคาบจากการดู; ใช้รายการอนุมัติเป็นฐานแล้วซ้อนเฉพาะข้อเสนอที่เลือก |
| S05 — ข้อเสนอและใบขออนุมัติ | รายการกรองครู/รอบลา/สถานะได้ มีปุ่มจำลองและทำใบขออนุมัติจากรายการเสนอ/รออนุมัติ | ใบหนึ่งไม่ปนผู้ขอหลายคน; ไม่มีรายการไม่เท่ากับไม่มีคาบสอน; ข้อเสนอเดิมยังเปิดต่อและตรวจคิวก่อนบันทึกจริงได้ |

แต่ละขั้นตรวจเองก่อนให้ผู้ใช้ดู หากขั้นนั้นเปลี่ยนหน้าจอให้ผู้ใช้ลองใช้และรับข้อเสนอแนะก่อนทำขั้นถัดไป ห้ามตีความการอนุมัติ S01 ว่าอนุมัติให้รื้อทุกขั้นพร้อมกัน
