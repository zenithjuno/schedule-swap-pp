# แบบเสนอปรับ UI ทั้งเว็บ

สถานะ: ผู้ใช้ยืนยันแบบครบ flow และอนุญาตชุด A เมื่อ 2026-11-11; ชุด B–F ยังมี gate ตามลำดับ ไม่ใช่การผ่าน S02 เดิม

## ผู้ใช้และผลลัพธ์

ครูผู้จัดแผนคัดคู่ด้วยตนเองบนคอมพิวเตอร์ มือถือใช้ดูและสื่อสาร งานหลักคือจัดทุกคาบในรอบลาเดียว แล้วแยกชุดไปคุยกับครูแต่ละคน โหมดการใช้งานเป็น Operate ความสำเร็จคือเทียบข้อมูลได้โดยไม่จำข้ามการ์ดยาว และนำตารางจำลองไปคุยก่อนอนุมัติได้

ข้อมูลและข้อจำกัดที่ยืนยันแล้วอยู่ใน `../PRODUCT.md` หลักฐานปัญหาคือ audit เดิมและ critique S02 ไม่ใช่ผลทดสอบกับผู้ใช้จริง คะแนนจัดอันดับช่วยตรวจเหตุผล ไม่ใช่ระบบเลือกแทนครู

## แนวที่เลือก

ผลหน้าเลือก `87b42c3a`: option `library`, code-led, ไม่มีการสลับเส้นทางสร้าง แนวภาพอ้างอิงป้ายและสิ่งพิมพ์ห้องสมุด ใช้เขียวอมฟ้าเข้ม พื้นเขียวอ่อน และพื้นที่ข้อมูลสีขาว ตัวไทย sans ที่อ่านง่าย ข้อมูลอยู่ในตารางปกติ ไม่ใช้ภาพเลียนแบบกระดาษหรือชั้นหนังสือ

ภาพร่างที่เลือก: `.impeccable/mocks/decision/library.html` เป็นหลักฐานองค์ประกอบหน้าเลือก ไม่ใช่โปรแกรมทำงานจริงหรือมาตรฐานทุกหน้าของเว็บ เมนูหลักบนสุด รายการคาบลาทางซ้าย ตารางเปรียบเทียบกว้างตรงกลาง และชุดที่เลือกอยู่แถบล่าง ต้องทำต่อให้ครบเนื้อหาล่างจอ สถานะต่าง ๆ และจอเล็ก ข้อมูลในร่างเป็นข้อมูลสาธิตที่ติดป้าย ไม่ใช้แทนข้อมูลจริงในรุ่นทดลอง

## ทางเดินและหน้าจอ

| พื้นที่ | งานและข้อมูลนำสายตา | การไปต่อ/ย้อนกลับ |
|---|---|---|
| แผนรอบลา | เปิดงานเดิมหรือเริ่มรอบลา แสดงคาบที่ยังไม่มีคู่และจุดที่ทำค้าง | กลับเข้าแต่ละคาบได้ ไม่ต้องเริ่มค้นหาใหม่โดยไม่จำเป็น |
| ระบุคาบ | ครู วันที่ และช่วงที่ลา ตารางเลือกคาบแสดงหลังยืนยันตัวครู | แก้ช่วงลาแล้วเห็นผลกระทบต่อคู่ที่เลือกไว้ ต้องตรวจใหม่ |
| คัดเลือกคู่ | รายการคาบซ้าย ตารางครู/วันคืน/คาบ/ห้อง/ข้อควรระวังกลาง ชุดที่เลือกด้านล่าง | เลือกทีละคาบภายในแผนเดียว เปิดข้อมูลภาระและเหตุผลคะแนนเพิ่มได้ ไม่บังคับเลือกอันดับแรก |
| ทบทวนแผน | ทุกคาบที่เลือกและยังไม่เลือก แยกตามครูปลายทาง ตรวจคาบซ้อนและข้อมูลเปลี่ยน | กลับแก้เฉพาะคาบได้ การแก้คู่หนึ่งต้องตรวจผลต่อแผนร่วม |
| ชุดคุยรายครู | ใครสอนอะไร วันไหน สองฝ่ายรับผิดชอบอย่างไร ตารางเต็มสัปดาห์ก่อน–หลัง พร้อมเน้นคาบที่เปลี่ยน | ดูและพิมพ์ก่อนอนุมัติได้ เปลี่ยนครูหรือวันคืนแล้วสร้างจากข้อมูลล่าสุด ป้าย “ข้อเสนอ — ยังไม่อนุมัติ” ทุกส่วนที่สื่อสาร |
| เอกสารและอนุมัติ | เลือกข้อเสนอของผู้ขอคนเดียวในรอบลาเดียว ทำใบขออนุมัติได้ แยกคำสั่งอนุมัติจริงให้ชัด | คุยไม่ลงตัวกลับไปคัดใหม่ ไม่มีการอนุมัติเพียงเพราะเปิด/พิมพ์ข้อเสนอ |
| ตารางที่มีผลจริง | ใช้รายการอนุมัติแล้วเป็นฐาน ระบุครูและสัปดาห์ชัด | ไปดูเอกสาร ประวัติ ถอน/ยกเลิกตามพฤติกรรมที่รองรับ โดยตรวจผลกระทบก่อนบันทึก |

เมนูหลักที่เสนอ: **แผนรอบลา / ตารางที่มีผลจริง / ประวัติและเอกสาร / ข้อมูลและตั้งค่า** คู่มือเข้าถึงได้จากบริบทและเมนูช่วยเหลือ จะตรวจทุกคำสั่งของ 7 แท็บเดิมและระบุปลายทางก่อนรวมเมนู ไม่ตัดความสามารถเพราะไม่มีในภาพร่าง

โหมดสอนแทนต้องมีทางเข้าในแผน และบอกความแตกต่างจากแลกคาบ: ไม่บังคับมีคาบคืนตามวิธีแลกเดิม แต่กติกาคัดครูและการบันทึกต้องออกแบบ/ตรวจแยกก่อนสร้าง ไม่สมมติว่าแค่เปลี่ยนป้ายชื่อโหมดแล้วใช้ได้

## ตารางสำหรับสื่อสาร

- ใช้ทั้งสัปดาห์เป็นค่าเริ่มต้น แสดงวันและวันที่จริงของสัปดาห์นั้น รวมทุกคู่ที่เลือกให้ครูผู้รับชุดเดียวกัน พร้อมรายการสรุปการเปลี่ยนที่อ้างถึงคาบในตารางได้
- แสดงทั้งสองฝ่ายก่อน–หลัง หากรับแทนกับคืนอยู่ต่างสัปดาห์ต้องแยกทุกสัปดาห์ที่ได้รับผล ไม่ยุบเป็นสัปดาห์สมมติ บนคอมเทียบข้างกันได้เมื่ออ่านไหว บนมือถือเรียงตามครูและสัปดาห์พร้อมหัวกำกับชัด
- ตารางจำลองใช้รายการที่อนุมัติจริงเป็นฐาน แล้วซ้อนเฉพาะชุดข้อเสนอที่เลือก ไม่เอาทุกตัวเลือกที่กำลังเปรียบเทียบมารวมกัน และไม่ซ่อนคู่ที่มีผลร่วมต่อการตรวจชน
- ยังไม่อนุมัติต้องไม่ไปอยู่ในตารางจริง การเปิดดูหรือพิมพ์ไม่เปลี่ยนจำนวนบันทึก สถานะ หรือการจองคาบ การพิมพ์ขาวดำต้องเข้าใจได้จากป้ายข้อความและตำแหน่ง ไม่อาศัยสีอย่างเดียว
- ไม่ส่งหาครูอัตโนมัติ รูปแบบส่งออกที่เพิ่มจากการพิมพ์ต้องตรวจขนาด ความครบของตาราง และความเป็นส่วนตัวก่อนตกลง ไม่ใส่ชื่อ/เบอร์หรือข้อมูลแผนใน URL

## สถานะและขนาดข้อมูล

ต้องออกแบบกรณีเริ่มต้นไม่มีข้อมูล นำเข้าเสีย พื้นที่ไม่พอ ไม่มีตัวเลือก หลายตัวเลือก หลายคาบ หลายครู หลายสัปดาห์ ชื่อและคำเตือนยาว แผนยังไม่ครบ ข้อเสนอชนกัน คุยไม่ตกลง แก้ข้อเสนอหลังทำเอกสาร ถอนอนุมัติ และเปลี่ยนภาคเรียน ข้อมูลจริงมีหลายพันแถวและภาคเรียนย้อนหลัง จึงไม่ถือว่าตัวอย่าง 4 ตัวเลือกในภาพเป็นเพดาน

ช่องเลือกครูมี label ที่เชื่อมกับช่องกรอก ชื่อที่พิมพ์ต้องตรงกับครูที่ระบบใช้ วันที่และคำเตือนอ่านได้ ปุ่มไม่มีผลต้องถูกลบหรือบอกเงื่อนไขที่ทำให้ใช้ได้ การค้นหาไม่มีผลไม่ใช่ข้อสรุปว่าไม่มีคาบสอน

บนมือถือหน้าหลักต้องไม่ล้นทั้งหน้า ตารางสัปดาห์เลื่อนเฉพาะในบริเวณตารางได้โดยคงหัววัน/คาบและบอกว่าดูของใคร การคัดเลือกยังทำได้แม้คอมเป็นอุปกรณ์หลัก แถบชุดที่เลือกต้องไม่บังคอนเทนต์หรือแป้นพิมพ์

## ขอบเขตและข้อที่ยังไม่ล็อก

- เปลี่ยนเฉพาะรุ่นทดลอง `/preview/` รักษา root `index.html` และข้อมูลเว็บเดิม รุ่นทดลองคงใช้สำเนาข้อมูลจริงแยกเขียน ระบบย่อข้อมูลและไฟล์สำรองเดิมต้องไม่เสีย
- ไม่เปลี่ยนสูตร/สถานะจัดเก็บ/กติกาลาไปพร้อมการแต่งหน้า การแก้บั๊กต้องมีค่าคาดหวังอิสระและตรวจว่าก่อนแก้ผิด หลังแก้ถูก
- ก่อนสร้างส่วนอนุมัติให้แมปการ “ตกลงกับครู” กับสถานะเดิมก่อน ไม่สร้าง enum หรือย้ายข้อมูลเอง หากสถานะเดิมไม่พอจึงเสนอการเปลี่ยนเฉพาะจุด
- ต้องยืนยันกติกาวันคืนที่อยู่วันเดียวกับการลาบางคาบก่อนแก้ F04 กรณีนี้ไม่ขวางการสร้างโครงหน้า แต่ขวางการรับรองความถูกต้องและผลจำลองที่เกี่ยวข้อง
- ยังไม่กำหนดให้มีลิงก์ออนไลน์ส่งข้อเสนอหรือระบบครูหลายบัญชี ไม่เพิ่มบริการภายนอกเพื่อทำ UI ใหม่

## เกณฑ์ตัดสินแบบ

ผู้ใช้หาได้ทันทีว่ากำลังจัดคาบไหน เหลืออะไร เปรียบเทียบใครบ้าง เลือกอะไรไว้แล้ว และจะนำชุดไหนไปคุย ครูผู้รับข้อเสนอเห็นหน้าที่ของทั้งสองฝ่ายและวันจริงได้ โดยไม่มีขั้นตอนอนุมัติหลอก ข้อมูลเดิมยังตรวจย้อนหลังได้ ทั้งเว็บใช้ภาษาสถานะเดียวกัน

ขั้น shape จบและผู้ใช้ยืนยันแบบแล้ว การสร้างชุด A ดำเนินต่อภายใต้ S02A ใน construction plan; ชุด B–F ยังไม่เปิด gate
